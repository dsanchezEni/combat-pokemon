= Fiche ressource — L'API Tyradex
:toc: left

Documentation officielle : https://tyradex.app/docs

== URL de base

----
https://tyradex.app/api/v1
----

Tous les endpoints du TP commencent par cette URL. L'API est en **GET**,
gratuite, sans clé d'authentification, renvoie du **JSON**, et autorise toutes
les origines (CORS `*`), donc `fetch` fonctionne depuis n'importe quel site
servi en `http://localhost` ou `https://` (GitHub Pages compris).

== Endpoints utilisés dans le TP

[cols="2,3,3", options="header"]
|===
| Endpoint | Description | Exemple

| `GET /gen/1`
| Liste des 151 Pokémon de la génération 1 (objets **complets** : stats, résistances...).
| `https://tyradex.app/api/v1/gen/1`

| `GET /pokemon/{id}`
| Fiche détaillée d'un Pokémon (par numéro Pokédex ou par nom anglais).
| `https://tyradex.app/api/v1/pokemon/25`

| `GET /pokemon`
| Liste de **tous** les Pokémon (plusieurs milliers : lourd, à éviter dans le TP).
| `https://tyradex.app/api/v1/pokemon`

| `GET /gen`
| Liste des générations (avec bornes `from`/`to` du Pokédex national).
| `https://tyradex.app/api/v1/gen`

| `GET /gen/{n}`
| Pokémon d'une génération donnée (n = 1 à 9).
| `https://tyradex.app/api/v1/gen/4`

| `GET /types`
| Liste de tous les types.
| `https://tyradex.app/api/v1/types`

| `GET /types/{type}`
| Détail d'un type.
| `https://tyradex.app/api/v1/types/electrik`
|===

== Champs d'un Pokémon (vérifiés sur l'API)

Exemple pour Pikachu (`GET /api/v1/pokemon/25`) :

[source,json]
----
{
  "pokedex_id": 25,
  "generation": 1,
  "category": "Pokémon Souris",
  "name": { "fr": "Pikachu", "en": "Pikachu", "jp": "ピカチュウ" },
  "sprites": {
    "regular": "https://raw.githubusercontent.com/Yarkis01/TyraDex/images/sprites/25/regular.png",
    "shiny": "https://raw.githubusercontent.com/Yarkis01/TyraDex/images/sprites/25/shiny.png"
  },
  "types": [
    { "name": "Électrik", "image": "https://.../types/electrik.png" }
  ],
  "talents": [
    { "name": "Statik", "tc": false },
    { "name": "Paratonnerre", "tc": true }
  ],
  "stats": {
    "hp": 45, "atk": 80, "def": 50,
    "spe_atk": 75, "spe_def": 60, "vit": 120
  },
  "resistances": [
    { "name": "Électrik", "multiplier": 0.5 },
    { "name": "Sol", "multiplier": 2 }
  ],
  "evolution": { "pre": [...], "next": [...], "mega": null },
  "height": "0,4 m",
  "weight": "6,0 kg",
  "egg_groups": ["Terrestre", "Féerique"],
  "sexe": { "male": 50.0, "female": 50.0 },
  "catch_rate": 190,
  "level_100": 1000000
}
----

[cols="2,4", options="header"]
|===
| Champ | Utilisation dans le jeu

| `pokedex_id` | Numéro affiché sur la carte ; sert aussi à appeler `/pokemon/{id}`.
| `name.fr` | Nom français affiché partout.
| `sprites.regular` | URL de l'image du Pokémon (hébergée sur GitHub, accessible partout).
| `types[].name` | Badges de type + filtre par type + multiplicateur de dégâts.
| `category` | La « catégorie » du Pokémon (ex : « Pokémon Souris »).
| `talents[]` | Tableau `{ name, tc }` (`tc` = talent caché).
| `stats.hp` | PV de départ du combattant.
| `stats.atk` / `stats.def` | Calcul des dégâts.
| `stats.spe_atk` / `stats.spe_def` | Attaque/défense spéciales (affichage fiche).
| `stats.vit` | Vitesse — pour aller plus loin : qui attaque en premier.
| `resistances[]` | Chaque entrée `{ name, multiplier }` indique l'efficacité d'un type
  contre ce Pokémon (`0` = immunisé, `0.5` = résistant, `1` = neutre, `2` = faible).
| `height` / `weight` | Taille et poids affichés dans la fiche.
|===

== Tester un endpoint dans le navigateur

Ouvrez directement l'URL dans un onglet, par exemple
`https://tyradex.app/api/v1/pokemon/25` : le navigateur affiche le JSON.
C'est le moyen le plus rapide de comprendre la structure des données.

== Appeler l'API en JavaScript

[source,javascript]
----
const reponse = await fetch('https://tyradex.app/api/v1/gen/1');
const pokemons = await reponse.json(); // transformation du JSON en objet JS
----

Points importants :

* `fetch` renvoie une **Promise** : on attend la réponse avec `await`.
* `reponse.json()` renvoie aussi une Promise : on l'attend aussi avec `await`.
* `fetch` ne signale pas une erreur HTTP (404, 500...) : il faut tester
  `reponse.ok` (voir étape 7). Exemple : `/api/v1/gen/1/pokemon` renvoie un 404
  (page HTML d'erreur), ce qui fait planter `.json()` — l'endpoint correct est
  `/api/v1/gen/1`.

== Bonnes pratiques exigées par Tyradex

* **Créditer** l'API dans votre page (lien vers tyradex.app).
* **Mettre en cache** les données (étape 7 avec `localStorage`) pour ne pas
  surcharger leurs serveurs.
* Ne pas utiliser l'API à des fins commerciales.
